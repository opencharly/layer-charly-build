# 2026.243.0912 — docs: stop pinning a CalVer in skill usage examples

## Summary

Usage examples inside this repo's skill documents (`content:` blocks) pinned hardcoded
CalVers. Those versions are guaranteed to rot: they cannot be kept current without
minting a release for every documentation edit, and while stale they teach versions
nobody should copy. They now read `:vTAG`, which never goes stale and fails fast if
pasted literally rather than silently building against an old pin.

The refs changed in this repo:

```
  @github.com/opencharly/layer-supervisord:v2026.240.0121
            becomes  @github.com/opencharly/layer-supervisord:vTAG
  @github.com/opencharly/pod-nested-podman-socket:v2026.243.0411
            becomes  @github.com/opencharly/pod-nested-podman-socket:vTAG
```

Only refs inside block scalars changed. The set of refs this repo RESOLVES is
unchanged -- charly never resolves a ref inside `content:`, so no dependency edge
moved.

## Correction

This entry replaces the one originally written for this release, which described a

because the PR body is written verbatim into this file at merge, the entry named a ref
from a different repository. The refs above are read from the merge commit itself

No code, packages, services, or plan steps changed in that release, and none change
