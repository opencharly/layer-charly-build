# 2026.261.1930 — docs(skill): make the docs skill's pins pin-agnostic

## Summary of changes

Removes two hard-coded, now-false pin claims from the `docs` skill entity (`charly.yml` → `docs-skill`), making them pin-agnostic so they cannot drift again.

- "…the plugin-docs CLI binary it builds at the pinned tag (**`v2026.254.1214`** …)" → "…at the **tag pinned in `deploy.yml`'s build step** …". The docs repo now pins `v2026.261.1812` (and was at `v2026.256.1653` before that), so the literal was already wrong.
- "**charly is pinned by a CI-time commit in `deploy.yml`** (**`d507ca5a…`** at the time of writing)" → "…**(the `checkout <sha>` in its charly-clone step)**". The live pin is `d45132f3…`.

These two lines are projected verbatim into the published site's `recipes/build/docs.md`, so the stale literals were live false statements about the docs repo's own workflow. Naming the mechanism instead of a value follows the same principle the docs workflow's own box-pin comment now uses.

**Closes / relates to:** surfaced by `opencharly/docs#126`, whose review found the regenerated `recipes/build/docs.md` asserting `v2026.254.1214` / `d507ca5a` while `deploy.yml` pins `v2026.261.1812` / `d45132f3`. Fixing the source here (then regenerating the corpus + site) is the correct cross-repo route rather than hand-editing a `DO-NOT-EDIT` page.

**Breaking change + rollback:** `none` — skill prose. Revert the merge to roll back.
